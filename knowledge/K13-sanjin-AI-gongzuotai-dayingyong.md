# 一、工作台的核心逻辑与定位

**工作台不是单纯工具集合**，而是把「输入、判断、执行、知识库沉淀」连接成一整个闭环，所有环节都在工作台内完成。每个界面**必须对应一个高频、具体、反复的工作场景**；如果没有对应场景，搭建出来的工作台就是空架子，使用频率低，最后不会再打开。

工作台背后依然由 Claude Code / CodeDesk（也可用 Workbody 等）执行，知识库沉淀到本地文档（Obsidian），工作台负责可视化。所以工作台的本质就是：**采集器 + 盯盘器 + 展示窗口**。

与**数字员工**的关系：两者没有上下层级，可以同步搭建。数字员工能定期上岗、主动执行任务并汇报，用户只需要看结果，不用每次去喊。

# 二、自用版与员工版：架构差异

- **自用版**：执行大脑用 Codex / Obsidian 这套本地工具，知识库存本地，无需额外成本。
- **员工版**：执行大脑改为调用需额外付费的 AI API，知识库脱离本地、部署到服务器（云端部署），工作台内置 AI。
- 无论哪种版本，**工作台本身只是前端展示层**，所有后端执行、数据存储逻辑由底层 AI 与工具完成。

# 三、工作台与工具的双向打通

- 工作台采集的所有数据**自动落进本地知识库**，存储位置由使用者自己定。
- 把浏览器插件的功能融入工作台后，可以解决「插件采集内容无法指定存储文件夹」的问题——插件基于浏览器下载，工作台本地运行则能指定。
- 反过来，Claude Code / CodeDesk 通过一条命令（如发一个关键词）就能调用工作台的全部采集能力，无需人工手动操作工作台。

# 四、工作台搭建实操方法

## 1. 前端页面生成

工作台本身是前端界面，直接用大白话告诉 Claude Code / CodeDesk：左边放对标监控、关键词挖掘等功能，右边展示每个功能的具体界面，它就能生成一个标准前端页面。

## 2. 后端功能对接

前端页面做好后，还要为每个功能配采集工具：告诉 AI「我有一个关键词采集插件，放在什么位置，请把功能融入工作台」，并明确每个功能对应的采集工具、工作流逻辑与工具存储位置，即可完成全量功能嵌入。

## 3. 需求提报规范

- 写清楚四件事：**做什么（给谁用）、最小可用版本长什么样、怎么样算成功**。
- 先把需求给 AI，**让它复述并列出还缺什么信息，不要直接动手开发**。
- 核心是把业务麻烦翻译成 AI 能理解的语言；具体工具怎么做不用管，那是 AI 的事。

## 4. 数据源选型

- 优先选第三方付费采集 API（主讲人用的工具口称「tiktok」，后称「TeaHub / GitHub API」，名称[待确认]）：支持小红书、抖音、微博等**十余个主流平台**，单次请求 **0.001 美金**。
- 充值（如 10 美金）后交给 AI，AI 会操控浏览器完成账号注册、配置、接入工作台的全链路对接。
- 无需自行开发爬虫逻辑：可唤醒后台**无头浏览器**，把插件功能装入其中完成采集（需扫码登录、记住登录状态），全程后台运行。

## 5. 存储路径设置

默认工作台没有保存设置，必须单独告诉 AI 保存位置，**每个目录对应知识库的文件夹**（与 Obsidian / Codex 的知识库路径打通），采完即被 AI 调用。做矩阵、多账号时还要做「切换存储位置」功能，避免所有数据堆到一起。

# 五、已落地工作台功能拆解（主讲人实操演示）

## 1. 总览与内容管理模块

- 首页优先展示当日优先级最高的待办事项；下设选题库、待发布、已发布、复盘记录、选题看板等标准化模块。
- **一文多发**：不同渠道（小红书/公众号/推特）排版风格不同，单独开发公众号排版工具，复制格式即可直接粘贴完成排版；各独立模块跑通后串联成完整工作流。
- **复盘看板**：数据复盘结果的集中展示区。

## 2. 每日复盘（AI 自动生成）

- 复盘来源依据有两个：①个人日历的时间块记录；②员工与 AI 的当日对话记录。
- 管理者可在工作台看到员工每天做了什么、哪些没做好、优先级与下一步建议，以及 AI 使用情况、工作推进进度。
- 系统能识别**「明显偏航」状态**——员工没做核心工作相关的事，即摸鱼了（例：主讲人前天在高铁上没跟 AI 对话，就被标为明显偏航）。

## 3. 关键词洞察

- 集成原插件**全部能力**（穷尽挖掘、意图挖掘、快速等高级选项与插件一模一样）。
- 支持两轮采集关键词、采集指定关键词下前 20 条笔记、选中有价值的笔记采集其评论；可导出词库给 Codex 用。
- 采集结果可「一键洞察」：依据是前一天富贵老师给的**千机塔**（[待确认]），输出人群洞察、意图分析、选题深化、评论需求、笔记分析等结果。
- 洞察结果可一键存入知识库 / 选题库；AI 可直接调用该功能采集，**不再需要插件**。

## 4. 账号对标分析

- 批量采集对标账号前 20 条笔记及内容链接；为省付费 API 成本，**只对高赞作品采集正文与逐字稿**，非高赞不采详情。
- 采集完可做账号快速分析；需要完整方法论时，**交给 Codex 结合知识库深度分析**。

## 5. 单篇笔记分析

- 对单条笔记做快速分析；背后是「API + 后台植入的自定义提示词（skill）」，提示词可让 AI 帮忙改。
- 原接的 OpenCloud 别人家 API 因中转站失效未续费；可灵活换接 **DeepSeek / OpenAI / Kimi / 通义千问 / 豆包** 等模型。
- 实现原理与这两天课程所学内容一致。

## 6. 电商冰盘：产品销量采集

输入自己经营的产品名/品类，搜索产品销量，采集前 20 个产品的当日数据，判断哪些产品、哪些 SKU 卖得火（工具名[待确认]）。

## 7. 雷达监控（主讲人认为最重要的功能）

- 定期监控对标账号、关键词/话题、博主、笔记数据；也支持小红书、抖音的商品销量监控。
- 可自定义**爆款阈值**：达到多少点赞、单轮上涨多少点赞就标为爆款线。
- 两种运行模式：**付费 API**（快、不费号）或 **仅浏览器/插件**（免费、费号、慢一点）；自动巡检无所谓速度，每天早上收菜即可。
- 需要一台**不关机的设备**（如 Mac mini）持续运行。
- 每周日 8:01 自动生成**巡查报告推送到飞书群**（如「七夕约会穿搭」双平台同热），飞书机器人拉进群全员可见；背后由 **Hermes 调用 Cortex** 做任务分配。

## 8. 热点功能

- 依托付费 API 抓取抖音、微博、小红书热榜及小红书灵感中心，整合到工作台方便选题。
- **雷达日报**是飞书报告的详细版；小红书有反爬，需手机扫码跳转打开（未做直接采集，省 API）。
- **热点快照**：每天热点趋势变化；当前设定每周更新，可改为每日。

## 9. 自动任务

选词、写稿、质检、内容流水线等 agent 是此前航海家大课分享过的内容，**只占工作台自动化流程的很小一部分**。工作台打通后，飞书只是反馈入口（也可发指令），但体感不如工作台好用。

## 10. Skill 仓库

- 集中存放所有 skill，直观查看每个 skill 的用途，比在 Obsidian 或文件夹里看清晰很多。
- 可再按「内容相关 / 分析相关」做二次分类；**分类交给 AI 完成**——不能在 skill 文件夹层面改路径，否则 Claude Code / Codex 等 agent 识别不到、调用不了。

## 11. 知识资产展示（可替代 Obsidian）

所有方法论等知识资产都可展示在工作台；当工作台做到完整极致时，**Obsidian 就不需要了**。相比 Obsidian 只能文件夹同步、部分员工使用的局限，工作台可部署云端、给每个员工分配独立账号与算力，更适配团队。

## 12. 工具抽屉（模块化接入）

自研工具、别人做的工具、过往自制虚拟产品都可统一接入工具抽屉，面向团队直接打开使用；**单点维护单个工具/文档**，改动不会对整个知识库造成代码影响、引发大量 bug。

## 13. 权限管理

- 按岗位分配账号权限：如运营总监全权限、普通运营只能看调研部分、销售看另一部分、老板看全部；可按岗位做组织架构隔离。
- 支持手机号/邮箱登录；**员工离职直接注销账号**，核心资产（skill 背后的知识库）带不走——即使复制走 skill 文件也用不了背后的东西。

## 14. 设置：模型、登录状态与存储

- **模型配置**：接入并保存 DeepSeek 等模型后，后台单篇笔记分析等所有功能都能调用该模型（后台每个功能都关联了提示词与 skill）；但此能力目前仅覆盖分析层面。
- **登录状态**：小红书、抖音等账号登录态；采集时通过无头浏览器扫码登录、自动记住状态，账号异常需重新扫码。
- **存储位置**：与知识库本地文件夹一一对应，采完即可被 Codex / skill 调用；支持多账号间切换存储位置。
- **固定数据**：工作台内部索引、内容生产等数据不可挪动（skill 路径定死）。
- **云端部署**：部署到云端后所有员工可共用 skill 工具仓库；可作为社群、知识付费、教育等场景的交付载体（如把一部分功能开放成产品，涉及爬虫的关键词洞察不开放）。

# 六、公域主页转化运营方案

## 1. 主页基础配置（主页三件套）

- 昵称、简介清楚说明：你是谁、一句话背书（为什么信任你）、关注你的理由、未来内容方向。
- 降低用户决策成本，提升主页转化效率。

## 2. 置顶笔记规则

固定放两条置顶笔记：一条是转化最高的产品介绍（或产品介绍），一条是公司实力背书；**验证过很多次，这两条转化率最高**。

## 3. 封面风格

让人一眼看出你是干嘛的；封面文字写得更清晰直白（我是干嘛的）。

## 4. 评论区运营（水军维护）

- 评论区必须手动维护；他人证言比自己说专业更可信。
- 用小号发：**用户证言**（「我也买了，一直在用」配图）、**互动引导类**内容（「不好闻回来骂」类）、**自黑类**不痛不痒的差评（如「产品好但发货慢」）——看起来真实，实则是好事。
- 权重逻辑：**评论权重最高**，多人在一条笔记下互动会把笔记权重顶上去，获得更多自然流量推荐，放大转化。

# 七、数据源与成本说明

- **TeaHub / tiktok 数据 API**（名称[待确认]）：0.001 美金/次请求；支持 TK、ins、YouTube、推特、抖音、B站、微博、微信/公众号、视频号、快手、领英、知乎等十余个平台（ASR 平台清单有噪音，按主流概括）；可采集笔记详情、用户资料、评论、搜索、热门、收藏等。
- **缺点是没有电商数据**（是自媒体数据源）；电商数据需另想办法。
- 接入方式：登录网站、扫码充值约 10 美金，其余交给 Codex 操控浏览器接入工作台，全程无需自己操作。
- **成本**：本地运行零额外成本，仅 API 成本；API 成本无上限，取决于使用频率。实测采几十个账号（每个前 20 条）+ 几千个关键词 + 评论，约花 **2 美金（约 14 元人民币）**，比较划算。
- **双路径冗余**：同时配置付费 API 与自有账号（免费插件）两条路径，API 挂了账号还能用；有订阅时分析能力直接用订阅，最省钱。
- **热点 API** 也是付费的（同 tiktok 数据源）；免费来源试用过不稳定。付费 API 最稳定、不伤号，费点钱。
- **套餐与 API 分开收费**：后台直接调用能力可在终端凭登录状态扣套餐额度；接外部 API 则按另外的规则收费、更贵。

# 八、电商数据获取：痛点与现有路径

- 电商数据没有公开通用 API，是行业公认痛点（从选品到采集）。
- 主讲人的来源：**灰豚数据**会员扒好的数据转存（其有约四五年的灰豚数据免费会员，来源为市场部赠送）。
- 可尝试解析**蝉妈妈、千牛**的数据接口。
- AI（Claude/Codex）道德感较强，直接让爬电商数据可能不干；需调整话术，如「我想学习一下电商每天的增长逻辑，想参考一下」。
